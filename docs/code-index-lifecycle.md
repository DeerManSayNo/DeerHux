# code_search 自动索引生命周期

打开项目（含尚未发送消息的草稿）后，ChatWindow 通过 useCodeIndex 调用 `POST /api/index/ensure`，后台创建本地文本索引。Session 启动和历史 Session 恢复也会独立启动该流程，不依赖界面请求。

- 同一进程、同一规范化 cwd 共用后台任务；并发刷新合并为同一个 Promise。
- 文件变更在 750 ms 的合并窗口后触发刷新；连续事件不会无限推迟刷新。每 30 秒进行一次兜底检查，覆盖不支持递归监听的平台和丢失的事件。
- 扫描仍遍历目录元数据，但复用 mtime、ctime 和大小未变的文件内容；重新读取变动文件并处理新增、删除、重命名。无变化不重写索引。快照仍为 JSON，变更后整体原子替换，不是逐条数据库写入。
- 保留原有文件大小、二进制和忽略规则，并排除 `.codegraph`、`.deerhux` 元数据目录。现有扫描器只处理根 `.gitignore` 的有限规则，并非完整 Git 忽略语义。
- 写入临时文件后原子 rename，避免查询读到半份 JSON。失败保留上次有效快照，由后续事件或轮询重试。
- 初次构建期间允许 Agent 使用其他工具。索引完成后，在空闲或下次回合开始前补注册 `code_search` 并重建工具摘要；正在运行的回合及其冻结工具列表不变。
- 用户手动关闭 `code_search` 后，刷新不会将它重新开启。切换 Agent 模式仍按该模式的工具预设处理。
- 工具目录和模型收到的工具定义都将已启用的 `code_search`、`codegraph` 排在前面。优先级由工具自身的简短描述表达，不再额外注入检索策略段落；使用边界保留在各工具定义中。
- Session 销毁时释放引用；项目界面使用 60 秒心跳、90 秒到期租约。最后一个使用者离开后关闭监听和定时检查，进行中的扫描可收尾。
- 默认目录为 `~/.deerhux/agent/indexes`，支持 `DEERHUX_CODING_AGENT_DIR` / `PI_CODING_AGENT_DIR` 配置。不依赖 Pi 模块在导入时的默认目录，避免初始化先后导致读写目录不一致。

这是本机关键词文本索引，不调用 Embedding API，也不下载模型。它仍是最终一致的快照；需要即时或穷举的文本结果时，使用 read / rg。

## 验证

`npm run test:code-index` 覆盖后台创建、并发合并、未变化源文件不重读、文件变更、忽略规则、引用释放、UI 临时租约、同 Session 补注册、回合隔离、提示词同步、实际搜索与用户手动工具选择。

2026-09-06 通过独立 30142 开发服务验证真实 HTTP 流程：没有预建索引的新项目创建 Session 后自动可搜索，编辑/重命名/删除均自动反映在搜索结果中；仅打开项目的 ensure 流程也会创建索引。测试没有发送模型任务。

`gee-notes` 已在正确的 DeerHux 目录建立 3,373 个文件的索引。使用新运行时恢复原 Session `01a072c1-e07e-7de6-a37f-8495237e0107` 后，实际工具列表包含 `code_search`。原先开发服务里已缓存的旧 Wrapper 需要重启开发进程或回收后恢复，才能加载新增生命周期代码；这不要求删除历史或新建 Session。
