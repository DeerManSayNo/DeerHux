# 界面交互规范

## 定时任务会话

- 左侧不再展示独立的定时任务折叠栏。定时任务生成的会话与普通会话共用「最近」列表，按最后活动时间排序，沿用最近 5 条的展示规则及打开、重命名、删除行为。
- 会话继续归属其工作目录，历史会话可在对应项目或搜索结果中找到；底部的定时任务管理入口负责配置与执行记录查看。
- 入口为 `components/SessionSidebar.tsx`，统一复用 `SessionItem`，不另行创建或复制会话。

## 左侧导航列表滚动条

- 桌面端采用 3px 圆角细线，使用 `text-dim` 的 55% 不透明度，轨道透明且不显示箭头；仅支持标准滚动条样式的浏览器回退到 `thin`。
- 项目与会话列表的滚动条默认透明，仅在鼠标悬停列表且发生滚动时显示；停止滚动 700ms 后淡出，鼠标移出时立即开始 180ms 淡出，再次悬停但未滚动时保持隐藏。
- 始终保留滚动条槽位，显隐不改变列表宽度；遵循系统减少动态效果偏好。入口为 `components/SessionSidebar.tsx`，样式为 `app/globals.css` 的 `.sidebar-navigation-scroll`。

## AI 回复中的链接

- 普通点击网页链接，在应用内预览；普通点击本地文件链接，打开文件预览。
- Command/Ctrl + 点击网页链接，通过系统默认浏览器打开。点击处理必须阻止 WebView 的默认跳转。
- Command/Ctrl + 点击本地文件链接，通过系统默认应用打开（HTML 文件通常为浏览器）；必须先识别文件路径，避免被解析为应用路由而出现 404。
- 桌面端外部打开失败时显示错误提示，不回退到 WebView 跳转。统一点击处理在捕获阶段执行。
- 统一点击入口位于 `components/AppShell.tsx`，作用于 `[data-ai-output] a[href]`；外部打开复用 `lib/external-links.ts` 的 `openExternalLink()`，桌面端使用 Tauri shell，浏览器端打开新标签页。

Markdown 渲染入口为 `components/MessageView.tsx`，相关基础样式位于 `app/globals.css`。

- 代码块高亮主题的 `pre` 背景统一由 `backgroundColor: var(--bg)` 指定；合并第三方主题前移除其 `background` 简写，避免明暗主题切换时与长属性冲突。

## 模型配置保存

- 新增模型允许暂存未填写的草稿；点击保存时，缺少模型 ID（含纯空白）必须提示供应商与模型序号，并选中对应模型，供用户填写或删除。
- 后端使用运行时模型加载器校验候选配置，校验通过后才替换生效文件；失败返回具体错误，保留原配置和偏好设置。
- 界面入口为 `components/ModelsConfig.tsx`，共享草稿校验为 `lib/models-config-validation.ts`，保存接口为 `app/api/models-config/route.ts`。

## 流式工具调用折叠

- 运行中的当前回合跨 assistant 消息统一计数，连续工具调用只保留最新 5 行，其余合并到「较早的工具调用 · N 个」。工具参数和结果继续点击工具行展开。
- 收到首个非空正文片段时，之前的工具全部折叠；正文之后的工具重新计数。工具返回文本、空白正文和思考内容不触发分段。各段入口保留原始顺序。
- 历史入口支持手动展开，流式更新、工具结果到达和消息落盘不重置展开状态；入口显示折叠工具中执行中和失败的数量。执行中只按工具运行事件维护的活动 ID 统计，不能根据缺少工具结果推断；已收到结果的工具不计入执行中。
- 展开「已处理」后，过程正文按原顺序显示，每段工具仍合并为默认收起的「工具调用 · N 个」；再展开该入口才显示工具行，参数和结果仍按需点击。关闭再打开「已处理」会重置内层工具分组为收起状态。
- 运行结束沿用既有「已处理」过程折叠与最终回答展示；没有最终回答的异常结束继续遵循现有行为。
- 用户在底部时跟随输出；暂停追底时启用浏览器滚动锚定，自动折叠不能主动恢复追底。
- 用户向上滚动离开底部时，在消息区域底部居中显示「回到底部」胶囊，输出中和输出结束后均可使用；点击后平滑滚动到底部并恢复追底，胶囊隐藏。
- 分组规则位于 `lib/streaming-tool-layout.ts`；接入位于 `components/ChatWindow.tsx`，展示位于 `components/MessageView.tsx`。

- 「已处理」展开区末尾若为工具分组，由外层统一绘制与总结之间的分隔线，末尾工具分组不重复绘制底边线。

## 对话框添加文件

- 粘贴、拖拽和左下角「上传文件」按钮采用相同规则：图片进入现有图片附件链路，展示图片预览并随消息发送；非图片文件保留原始路径，展示右侧引用胶囊，不复制到项目。
- 桌面端文件选择器支持任意类型、多选；剪贴板和原生拖拽提供原始路径。应用内文件列表拖拽提供路径载荷；重复非图片路径去重。
- 网页端有图片内容时直接作为图片附件；非图片无法取得原始路径时提示使用桌面端或应用内拖拽，不根据文件名猜测路径。
- 图片通过 `/api/chat-image-upload` 保存至现有聊天图片目录，支持图片内容和原始图片路径两种入口；取消选择不改动输入。
- 入口为 `components/ChatInput.tsx`、`hooks/useDragDrop.ts`、`components/FileExplorer.tsx`；剪贴板路径解析为 `lib/clipboard-file-paths.ts`，桌面读取命令为 `read_clipboard_file_paths`。
- 图片添加后立即显示附件卡片；粘贴有本地预览时先显示缩略图，只有原路径时先显示同尺寸占位。两者均在保存期间显示相同转圈并暂停发送，成功后替换为就绪预览；失败移除卡片并提示，处理中移除的卡片不会在完成后重新出现。

- 拖拽遮罩以每个 session 的聊天窗口为范围：覆盖该窗口的消息区、空白区和输入区，不覆盖应用侧边栏及其他聊天窗口。落在哪个 session 就添加到哪个 session，不依赖原先焦点。拖出该窗口或结束拖拽后收起遮罩；桌面原生事件按实际落点命中对应聊天窗口。

- 原生拖拽坐标按平台转换：当前 Wry 0.55.1 在 macOS 返回逻辑点，不能再直接除以 Retina 像素比；其他平台按物理像素转换。统一由 `lib/native-drag-position.ts` 处理，悬停遮罩和松开落点共用同一转换，并计入 WebView 缩放。

## 全选范围

- 输入框和可编辑区域保留原生 Command/Ctrl+A，仅选择编辑内容。
- 聊天区的 Command/Ctrl+A 限定在该 session 的消息区域，不跨到其他 session、侧边栏或输入工具栏；有消息选区时优先沿用其所属 session。
- 聊天消息保持可拖选复制，按钮、会话列表项和输入工具栏不参与普通文本选择。入口为 `hooks/useChatSelectAll.ts`，由 `components/ChatWindow.tsx` 接入。

- 消息区仅用户正文、AI 正文及代码内容可选；时间、模型名、系统提示词入口、处理状态、代码语言标签、行号和复制按钮不显示选区。复制选区时同样过滤这些元信息，保留正文段落与代码换行。正文使用 `data-message-body` 标记，代码工具栏使用 `data-selection-ignore`。

- 代码块的选中背景仅覆盖代码行的实际文字宽度，不覆盖容器内边距和行尾剩余宽度；保留源代码的缩进与真实空行，不以裁剪代码内容实现视觉效果。
