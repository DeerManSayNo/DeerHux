# DeerHux 设计系统

## 视觉基础

参考用户提供的 Orchestra 工作台截图，采用中性灰白表面、橙色操作强调、银灰导航选中态、绿色成功与玫红异常。颜色为依据参考图重新制定的语义配色，未声称精确取样。面向长时间阅读代码、管理会话与执行工具的工作台，统一导航、对象上下文、内容与就地操作的层级，保留业务能力，调整布局与视觉密度。

- 中性表面承担绝大部分面积；橙色仅用于主操作、当前选择、焦点和品牌标记，不用于大面积背景或正文染色。
- 应用底层为连续银纸材质，导航直接置于其上；每个 session 都是独立的白色圆角窗口，窗口间隙露出公共背景，不设置包住所有窗口的大白板。右侧资源区是独立面板。深色保留相同结构，使用石墨银灰底层与独立深色窗口。
- 单一操作区保留一个主操作；共用工具按钮不绘制背景方框，以图标／文字颜色表达状态，保留图标规范与悬停说明。
- 视觉优先做减法：背景局部保留银纸折光，靠近内容边缘回到近白；结构依靠留白与轻微表面差异建立，避免窗口描边、输入框描边、内部分隔线、标签彩边与阴影同时争抢注意力。窄 session 降低辅助信息强度，保留完整可操作的内容与清楚的键盘焦点。
- 品牌亮橙 `brand` 用于品牌元素；`action` 与 `action-foreground` 保留为品牌及特定实心动作的配色令牌；主工作区工具按钮不使用实心底色，发送状态改由 accent 箭头表达。文字链接使用更深的 `accent`；历史 accent 实心按钮搭配 `accent-foreground`。导航创建入口采用中性透明底，当前项目或会话使用更明确的银灰选中面，避免依赖浅橙／深棕的低对比染色。

### 硬编码色值替换表

首页已确认的语义令牌是唯一颜色来源。二级窗口与延伸页面存量代码把 Tailwind 默认色当状态色使用，深浅主题下不会适配，必须按下表替换。**禁止在任何组件中再写裸色值**（`#rrggbb`、`rgb()`、`rgba()`），色值只能出现在 `app/globals.css` 与 `app/design-tokens.css`。

| 存量硬编码 | 出现次数（约） | 替换为 | 说明 |
| --- | --- | --- | --- |
| `#ef4444`、`#f87171`、`#dc2626` | 80+ | `var(--danger)` | 失败、删除、错误文字 |
| `rgba(239,68,68,0.08)`、`rgba(239,68,68,0.06)` | 18+ | `var(--danger-bg)` | 错误块底色 |
| `rgba(239,68,68,0.2)` ～ `0.45)` | 20+ | `color-mix(in srgb, var(--danger) 35%, transparent)` | 错误块描边 |
| `#22c55e`、`#4ade80`、`#16a34a` | 60+ | `var(--success)` | 连接成功、已完成、新增文件 |
| `rgba(34,197,94,0.1)`、`rgba(22,163,74,0.12)` | 6+ | `var(--success-bg)` | 成功块底色 |
| `#f59e0b` | 2 | `var(--warning)` | 未支持、等待确认 |
| `#fff` / `#000` 作前景或背景 | 40+ | `var(--bg)` / `var(--text)` / `var(--accent-foreground)` | 按语义选择，禁止纯黑白 |
| `rgba(0,0,0,0.35)`、`rgba(0,0,0,0.45)` | 18+ | `var(--shadow-overlay)` / `var(--shadow-overlay-strong)` | 弹窗遮罩 |
| `0 18px 60px rgba(0,0,0,0.28)`、`0 16px 48px #0003` | 10+ | `var(--shadow-modal)` | 二级窗口阴影 |
| `0 8px 24px …` 类浮层阴影 | — | `var(--shadow-popover)` | 菜单、下拉、浮卡片 |

语义选色规则：状态色只承担「状态」，不承担「层级」。例如错误提示用 `--danger` + `--danger-bg`，但其容器层级仍靠留白与底差表达，不给错误块再加阴影。项目作用域等次级标签用 `--accent` 文字色表达，不给标签加彩色底。

## 按钮系统

此前二级窗口没有统一按钮组件，`McpConfig`、`MemoryConfig`、`RoleConfig`、`WeChatConfig` 各自定义 `primaryBtnStyle / secondaryBtnStyle / dangerBtnStyle / smallBtnStyle / closeBtnStyle`，圆角在 7/9/10/14px 之间摇摆，硬编码色值分散。统一入口为 **`components/ui/Button.tsx`**，形态定义在 `components/ui/Button.module.css`。

```tsx
<Button variant="primary" onClick={save}>保存</Button>
<Button variant="secondary" leadingIcon="add">新增</Button>
<Button variant="danger" disabled={!canEdit}>删除</Button>
<Button variant="iconButton" icon="close" aria-label="关闭" onClick={onClose} />
```

五型按**操作层级**划分，同一个操作区只出现一个 `primary`：

| variant | 用途 | 视觉 |
| --- | --- | --- |
| `primary` | 该操作区唯一主操作（保存、确认、创建） | 实心 `accent`，文字 `accent-foreground`，无边框 |
| `secondary` | 常规次操作（测试连接、新增、选择） | `bg-panel` 底 + 1px `border`，文字 `text` |
| `ghost` | 撤销、取消等弱操作 | 透明底，`text-muted`；悬停 `bg-hover` + `text` |
| `danger` | 删除、停止等破坏性操作 | `danger-bg` 底 + `danger` 30% 描边 + `danger` 文字 |
| `iconButton` | 纯图标工具按钮 | 透明底无边框，沿用 `tool-buttons.css` 前景色状态机 |

尺寸两档，与点击区绑定，不靠内边距凑数：`md` 32px 高（默认）、`sm` 26px 高（面板标题行、密集操作）。纯图标按钮为正方形（`md` 32×32、`sm` 26×26），必须提供 `aria-label`。

状态规则：禁用统一 `opacity: 0.5` + `cursor: not-allowed`，并保留真实 `disabled` 属性；悬停只改底色与文字色，不改圆角与尺寸；键盘 `focus-visible` 使用 2px `accent` 外轮廓、2px 偏移；`prefers-reduced-motion` 下取消过渡。
`iconButton` 的 `aria-pressed` / `aria-expanded` / `data-active` 表达选中，用 `accent` 文字色，**不加背景块**——这与 `tool-buttons.css` 的既有规则一致。
圆角固定 `--radius-control`（6px），调用方不得覆盖。原 `primaryBtnStyle` 的 `color: "white"` 属于深浅主题都不适配的写法，统一改为 `var(--accent-foreground)`。
`Button` 不接受 `size` 以外的形态参数；特殊形态（如 30px 圆形发送按钮）继续走各自专用实现，不通过扩参实现。

## 二级窗口与弹层

设置类弹窗此前在每个模块内重复定义 `overlayStyle / modalStyle / asideStyle / asideHeaderStyle / mainHeaderStyle / titleStyle / subStyle / closeBtnStyle`，外壳尺寸、圆角、阴影、遮罩与关闭按钮各不相同。统一入口为 **`components/ui/Modal.tsx`**，形态定义在 `components/ui/Modal.module.css`。

外壳负责：遮罩与层级、Escape 关闭、点击遮罩关闭、Tab 焦点循环与关闭后焦点恢复、窗口圆角与阴影、滚动容器（`app-scrollbar`）、关闭按钮。业务模块只提供内容，**不再自行定义 overlay / modal / 关闭按钮样式**。

两种布局：

- `split`：左列表栏（`sidebar` + `sidebarFooter`）+ 右主区（`children` + `actions`）。尺寸 `min(1040px, 100vw-40px)` × `min(780px, 100vh-40px)`，`--radius-window`（16px），`--shadow-modal`。左侧栏 280px、`bg-panel` 底、右分隔线；主区标题行由 `actions` 插槽承载。
- `confirm`：居中窄弹窗，`min(480px, 100vw-40px)`，`bg-panel` 底，`--radius-composer`（12px），`--shadow-popover`，操作行由 `footer` 插槽右对齐。

遮罩使用 `--shadow-overlay`（浅色 35% / 深色 50%），不用固定 `rgba(0,0,0,0.35)`。层级引用令牌：二级窗口 `--z-window`(1000)、嵌套弹窗 `--z-window-raised`(1100)、二次确认 `--z-dialog`(2000)、阻塞式确认 `--z-modal`(2100)、全局提示 `--z-toast`(9000)；新增浮层不允许写裸 `zIndex`。

表单与列表的通用类由 **`components/ui/Form.module.css`** 提供：`form / gridTwo / label / input / textarea / select`（表面）、`scopeButton / scopeRow / scopeName / scopeMeta / pill`（列表项）、`dot / dotSuccess / dotWarning / dotDanger / dotNeutral`（状态圆点）、`hintBox / errorBox / statusRow / centeredEmpty`。模块 CSS 只写自身特有布局，不复制这些声明。

## 滚轮系统

统一入口为 `app/globals.css` 的 **`.app-scrollbar`**：4px 圆角细线、轨道透明、不显示箭头，thumb 常态 `border` 色、悬停 `text-dim`；同时设置 `scrollbar-width: thin` 与 `scrollbar-color` 作为标准属性回退。

- 二级窗口、弹窗、面板与任意内部滚动容器加 `.app-scrollbar`。`ModalShell` 已为左栏与主区自动应用。
- 需要完全隐藏滚动条的场景使用 `.scrollbar-none`。
- 侧栏列表滚动条是**独立语义**，继续使用 `.sidebar-navigation-scroll` 的悬停显隐与 700ms 淡出规则，不复用 `.app-scrollbar`。
- 全局 `::-webkit-scrollbar` 4px 基线保留，作为未标注容器的兜底。

## 字体系统

字体族沿用系统无衬线与既有等宽字体（`--font-mono`）。字号、字重、行高此前完全没有令牌，全站内联 `fontSize` 硬编码 500+ 处（12px 214 次、11px 138 次、13px 68 次、10px 53 次），字重在 500/600/700/800 之间混用；二级窗口还出现 9px 与 48px 的孤立值。令牌定义在 `app/design-tokens.css`。

字号六档，按**用途**而非视觉微调选择：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--text-2xs` | 10px | 徽标、极紧凑元数据 |
| `--text-xs` | 11px | 分组标题、辅助说明、pill |
| `--text-sm` | 12px | 次级正文、按钮、表单标签、表单元数据 |
| `--text-base` | 13px | 列表主文本、表单输入值、正文紧凑档 |
| `--text-lg` | 15px | 面板标题、正文阅读档 |
| `--text-xl` | 16px | 二级窗口标题、区块标题 |

字重四档：`--weight-regular` 400、`--weight-medium` 500、`--weight-semibold` 600、`--weight-bold` 700。**禁止使用 800。** 此前 `fontWeight: 800` 的标题统一降为 `semibold`。

行高三档：`--leading-tight` 1.35（单行控件、标题）、`--leading-normal` 1.55（表单说明、元数据）、`--leading-relaxed` 1.7（正文段落）。

规则：新增界面文本一律引用令牌，不写裸数值；字号不随视口缩放，字距 0；正文 14px 保留在全局基线（`html` 的 `font-size`）与 Markdown 正文，不作为组件级字号令牌。9px、48px 等孤立值在下一次改造中归并到最接近档位，不新增档位。

## 阴影系统

此前阴影只有 `--shadow-control` 一个令牌，二级窗口硬编码 `0 18px 60px rgba(0,0,0,0.28)`、`0 16px 48px #0003` 等值，深浅主题不区分。令牌定义在 `app/globals.css`，**必须成对定义**（`:root` 与 `html.dark`）。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--shadow-control` | `0 1px 2px #20202208, 0 4px 12px #20202205` | 对应深色 | 已确认控件的轻柔外阴影（首页既有） |
| `--shadow-popover` | `0 8px 24px #2020221a` | `0 8px 24px #0000004d` | 菜单、下拉、浮卡片、`confirm` 弹窗 |
| `--shadow-modal` | `0 18px 60px #20202247` | `0 18px 60px #0000008c` | 二级窗口 |
| `--shadow-overlay` | `rgb(0 0 0 / 0.35)` | `rgb(0 0 0 / 0.5)` | 弹窗遮罩 |
| `--shadow-overlay-strong` | `rgb(0 0 0 / 0.45)` | `rgb(0 0 0 / 0.6)` | 阻塞式确认遮罩 |

规则：阴影只用于表达「浮起层级」，不用于描边、装饰或强调；**不能用阴影模拟边框**（与边框原则一致）；同一元素不同时使用边框、内描边和阴影；常态结构不使用阴影，仅浮层与已确认的控件例外。深色模式阴影需要更强不透明度才可辨识，因此成对定义而非共用一份。

## 图标系统补充

图标子系统已在前文「图标系统」定稿（`AppIcon` 四档尺寸、1.75 描边、语义名称表），是本次总结中质量最高、最接近完成的一环，无需调整。二级窗口改造时的补充要求：

- `Button` 的 `icon` / `leadingIcon` 属性内部调用 `AppIcon`，调用方不再手写 `<svg>` 或直接引入 lucide 组件。
- 弹窗关闭按钮统一使用 `Button variant="iconButton" icon="close"`，替换存量文字 `×`。
- 「新建」类操作使用 `leadingIcon="add"`（Plus），替换存量文字 `+`。
- 状态圆点（连接成功、未启用）沿用 `dot` 系列类，不手写 `borderRadius: 99` 的内联 span。

## 边框使用原则

- **默认无边框。** 先用留白、对齐、字号／字重与轻微底色差异表达层级。可点击、选中、展开或带圆角，都不构成添加边框的理由。
- 仅在需要界定独立窗口、识别输入区域、区分容易混淆的操作范围时考虑边框。新增描边需明确它承担的功能，并检查父级是否已经提供足够边界；同一局部不要叠加外框、内部分隔线、子项描边和阴影。
- border、环形 outline、inset box-shadow 产生的内描边都计入边框。不能用阴影模拟描边来绕过无框规则；装饰性阴影同样默认不加。
- 必要的常态结构线使用对应语义令牌，保持低对比、1px，不用强调色整圈描边。键盘 focus-visible 属于可访问性状态，保留清楚的焦点提示；不能为追求无框而移除必要的键盘反馈。
- 已确认无框的区域：侧栏选中项目／会话、正文行内代码、技能与文件引用标签、最新提示词摘要及展开内容。它们不添加常态边框或内描边，辅助操作间不绘制竖向分隔线。默认无阴影；最新提示词容器与主输入框按用户确认的各自专用规则允许轻柔外阴影，不推广到其他区域。
- 独立 session 与主输入框现有浅边界继续按各自专用规则处理，不把这次调整扩展成全局删框。后续修改存量模块时复核其边框必要性，优先消除重复边界。

## 组件与尺寸

- 字体沿用系统无衬线与现有等宽字体。正文 14px（全局基线与 Markdown 正文），辅助信息与面板标题见「字体系统」令牌表；字距 0，字号不随视口宽度缩放。
- 间距以 4px 为步距，常用 4 / 8 / 12 / 16 / 24px。常规按钮高 32px、紧凑按钮 26px，表单高 36px；已有 28px 窗口工具栏、30px 圆形发送按钮继续按专用规则执行。
- 圆角统一走「圆角系统」令牌，不在此重复档位定义。页面分区使用平面布局，避免卡片嵌套。现有输入框、圆形按钮等已确定的专用形态保留。
- 共用工具按钮所有状态保持透明底色、无边框和阴影：常态 text-muted，hover 为 text，选中／展开为 accent，按下为 accent-hover，禁用为 text-dim。选中或展开状态通过 aria-pressed / aria-expanded 表达，不能靠背景方框。会话列表的选中面、输入框和原生红绿灯属于独立语义，不套用工具按钮重置。

## 圆角系统

统一数值入口为 `app/design-tokens.css`，由根布局 `app/layout.tsx` 导入，深浅主题共用。组件按语义引用令牌，不单独写 5、7、9、10、12、14、15px 等数值，也不混用另一套 rounded 工具类。

| 令牌 | 数值 | 使用角色 |
| --- | --- | --- |
| `--radius-small` | 4px | 行内代码、技能／文件引用标签、小徽标 |
| `--radius-control` | 6px | 普通按钮、菜单项、列表选中面、最新提示词条 |
| `--radius-panel` | 8px | 普通输入区域、下拉面板、弹窗、消息气泡、代码及工具详情容器 |
| `--radius-composer` | 12px | 主聊天输入框，深浅主题及紧凑模式共用 |
| `--radius-window` | 16px | 独立 session、资源／预览窗口 |
| `--radius-circle` | 50% | 等宽高头像、状态圆点、圆形按钮 |
| `--radius-window-inner` | 外角减 1px | 紧贴 1px 窗口边框的标题背景和正文底角 |

- 同角色在不同页面及紧凑模式中共用同一档位，hover、按下、选中、聚焦不改变圆角。尺寸与圆角分开定义，不能靠不同圆角补偿按钮尺寸或对齐问题。
- 贴合外框的内部表面使用继承、裁切或由外角减边框厚度计算；15px 内角属于 16px 外角的派生值，不是独立档位。内容内部的输入工具和弹出菜单仍使用自己的语义角色。
- 普通标签不做胶囊。二态开关轨道按自身高度的一半计算圆角，属于几何特例；品牌 Logo、原生窗口红绿灯和滚动条的几何轮廓单独管理。
- JSX 可用 `borderRadius: "var(--radius-panel)"`；CSS 使用对应变量。`radius-small`、`radius-control`、`radius-circle` 提供常用类，不改变背景、边框、阴影或点击区域。
- 已迁移：AppShell、ChatWorkspace、ChatWindow、ChatInput、SessionSidebar、MessageView、SendIconButton、ProjectBranch、ChangedFilesList，以及工作区、行内代码、窗口微信和文件菜单样式；全局 Markdown 代码面板与侧栏工具圆角也接入令牌。其他设置业务模块与分享页仍有历史值，后续按角色迁移，不宣称已全量替换。
- 回归检查为 `node scripts/test-radius-tokens.mjs`，验证令牌档位、根布局加载、已迁移模块无新增硬编码圆角及窗口内角派生规则。

## 最新提示词摘要

- 最新提示词采用无边框摘要行，底色与 session 同为 bg，圆角 6px，允许一层轻柔外阴影增强与正文的层次：浅色 `0 2px 8px #0000000d`，深色 `0 2px 8px #00000026`。不加描边、内描边或光晕；定位按钮与折叠箭头之间不加竖线，展开内容上方不加横线，也不额外添加独立阴影。阴影样式限定在 workbench.css 的 `.latest-prompt`，不改变尺寸与交互。
- 摘要行最小高 32px，文字与图标使用中性文字色，12px Lucide prompt 图标；摘要按实际可用宽度单行省略，不固定截取 60 字。悬停仅提亮所属按钮的图标／文字，不添加按钮背景块，完整提示词可通过悬停或展开查看。
- 左侧按钮仅滚动所属 session 的消息容器，将原提示词顶部滚过消息视口内边界 2px，留出像素取整余量；一般受滚动范围限制时取最近可达位置。末尾提示词已经可见、顶部对齐不可达且当前已到底（1px 容差）时，在原有滚动范围内向上回滚 2px，不能继续向下滚或补尾部空白；不具备滚动空间时保持不动。暂停追底后的向上定位必须进入原有提示词位置判断，不被 near-bottom 分支提前返回。不使用 scrollIntoView，不能滚动页面、窗口外壳或其他 session。定位使用 requestAnimationFrame 驱动的 ease-out cubic（1 - (1 - t)^3）减速动画，按距离在 700～1200ms 内完成，越接近目标越慢；系统开启 prefers-reduced-motion 时即时定位。动画只驱动当前消息容器，连续点击先取消旧动画，再从当前位置向当时摘要对应的目标滚动，不建立额外索引切换逻辑。滚轮、触摸、消息区指针／滚动键操作、恢复追底、切换会话、组件卸载及历史补载恢复位置时取消动画。点击后暂停当前窗口自动追底，用户可通过「回到底部」恢复。实现为 `lib/chat-scroll-animation.ts`，对应测试 `scripts/test-chat-scroll-animation.ts`。
- 点击与手动滚动共用现有 handleScroll 的位置及方向判断：向更早消息定位时，仍在视野中的当前提示词会触发显示上一条；向更新消息定位时，当前提示词顶部已越过视口，触发显示下一条。连续点击由真实落点驱动，不在点击事件里强行增减提示词索引，不另建遍历方向或屏蔽滚动事件。实际无法继续滚动时保持目标，不循环。
- 补载更早历史时按 entryId 保持原提示词身份，不因索引整体移动而重置到最新一条。坐标转换与范围约束在 `lib/chat-message-scroll.ts`；回归测试 `scripts/test-chat-message-scroll.ts` 覆盖阈值、浮点取整、滚动范围及禁止点击强制切换。

## 工具调用活动行

- 当前未结束的工具段只在聊天流底部、输入框上方的状态区展示，替代该位置的普通阶段文案；执行、等待模型继续及恢复状态共用此行，诊断信息仍在下方。消息正文里不重复展示实时工具行，Token 用量保留在所属消息下方。正文持续流式输出时隐藏普通阶段文案；正文超过 600ms 未更新且回合仍在运行时恢复转圈和阶段文案，覆盖模型组装下一次工具调用参数但工具事件尚未到达的空窗。正文开始后原工具段转为消息中的历史分类摘要，回合结束时底部活动行消失；展开状态随同一分组迁移保留。

- 每条工具活动行及历史分类摘要的文字后显示 14px 折叠箭头：收起朝右、展开朝下；执行中的转圈独立展示，不替代箭头。调用次数和状态仍右对齐。

- 工具活动行、历史分类摘要及整轮过程与后续正文之间不绘制横向分隔线，使用现有留白区分内容。展开历史过程后，过程正文中的 Markdown 横线连同占位隐藏。历史内容间隔为 4px，工具行上下内边距各 2px，工具组不额外添加底部留白；空白正文块不占位。

- 当前回合的连续工具调用跨 assistant 消息合并成一个固定 24px 高的活动行；新调用到来时用 180ms 向上滚动切换文本，不再堆叠最近五个工具卡片。执行中、执行结束等待模型及工具后分析结果均显示对应工具类别，最多展示两项，更多项目显示总项数；普通类别去重，每次 bash 调用独立显示规范化后命令的前 10 个字符，便于区分不同命令。长内容单行省略，悬停可查看完整行摘要，遵循减少动态效果偏好。
- 收到非空正文后，之前的工具段收为分类摘要；正文之后的新工具开启新的活动行。工具返回文本、空白正文和思考不触发分段；流式与落盘重叠时按调用 ID 去重，分组和展开状态保持稳定。
- 历史摘要按工具类别去重：只有 bash 显示「运行了命令」，read + bash 显示「已读取文件并运行了命令」；其他类别包括查看目录、查找文件、搜索内容、查询代码关系、修改文件、写入文件和调用其他工具。按声明的工具类型分类，不猜测 shell 命令实际读写了哪些文件。
- 点击活动行或摘要可展开每次调用，继续点击工具查看参数和结果。活动行显示调用总数、正在执行数和失败数；只以真实活动 ID 判断执行中，已返回结果的不再计入。等待执行与失败明确显示，分类摘要不表示全部成功。
- 完成后的整轮过程入口也使用分类摘要并附耗时；展开后保留过程正文与按段归类的工具记录。没有最终正文、停止或异常结束也收起工具列表，错误提示继续可见。历史思考保持隐藏。
- 用户在底部时跟随输出；暂停追底时不主动恢复。向上滚动后保留「回到底部」按钮。分组与分类位于 `lib/streaming-tool-layout.ts`，接入位于 `components/ChatWindow.tsx`，展示与样式为 `components/MessageView.tsx`、`components/tool-activity.css`。

## 对话框添加文件

- 粘贴、拖拽和左下角「上传文件」按钮采用相同规则：图片进入现有图片附件链路，展示图片预览并随消息发送；非图片文件保留原始路径，展示右侧引用胶囊，不复制到项目。
- 桌面端文件选择器支持任意类型、多选；剪贴板和原生拖拽提供原始路径。应用内文件列表拖拽提供路径载荷；重复非图片路径去重。
- 网页端有图片内容时直接作为图片附件；非图片无法取得原始路径时提示使用桌面端或应用内拖拽，不根据文件名猜测路径。
- 桌面端读取剪贴板原始路径失败时，仍使用剪贴板中已有的图片内容添加附件；混合粘贴中无法取得路径的非图片文件继续显示路径提示。
- 图片通过 `/api/chat-image-upload` 保存至现有聊天图片目录，支持图片内容和原始图片路径两种入口；取消选择不改动输入。
- 入口为 `components/ChatInput.tsx`、`hooks/useDragDrop.ts`、`components/FileExplorer.tsx`；剪贴板路径解析为 `lib/clipboard-file-paths.ts`，桌面读取命令为 `read_clipboard_file_paths`。
- 图片添加后立即显示附件卡片；粘贴有本地预览时先显示缩略图，只有原路径时先显示同尺寸占位。两者均在保存期间显示相同转圈并暂停发送，成功后替换为就绪预览；失败移除卡片并提示，处理中移除的卡片不会在完成后重新出现。

- 拖拽遮罩以每个 session 的聊天窗口为范围：覆盖该窗口的消息区、空白区和输入区，不覆盖应用侧边栏及其他聊天窗口。落在哪个 session 就添加到哪个 session，不依赖原先焦点。拖出该窗口或结束拖拽后收起遮罩；桌面原生事件按实际落点命中对应聊天窗口。

- 原生拖拽坐标按平台转换：当前 Wry 0.55.1 在 macOS 返回逻辑点，不能再直接除以 Retina 像素比；其他平台按物理像素转换。统一由 `lib/native-drag-position.ts` 处理，悬停遮罩和松开落点共用同一转换，并计入 WebView 缩放。

## 全选范围

### 主聊天区滚动跟随

- 流式输出期间，用户向上滚动立即暂停追底，包括仍处于底部 80px 范围内的轻微上拉；滚轮、触摸移动和键盘上翻采用相同规则。消息内独立滚动区域按实际滚动归属处理。
- 暂停后，新内容、输出结束和自动折叠均不恢复跟随。用户主动向下滚回底部 80px 范围，或点击「回到底部」后恢复；按钮即时定位，避免平滑动画与流式更新竞争。
- 使用 ResizeObserver 观察消息内容和视口尺寸，仅在跟随状态下调整底部位置。输入意图与尺寸变化分开处理，不使用定时过期的用户滚动标记。入口为 `lib/chat-scroll-follow.ts` 和 `components/ChatWindow.tsx`。

### 选区行为

- 输入框和可编辑区域保留原生 Command/Ctrl+A，仅选择编辑内容。
- 聊天区的 Command/Ctrl+A 限定在该 session 的消息区域，不跨到其他 session、侧边栏或输入工具栏；有消息选区时优先沿用其所属 session。
- 聊天消息保持可拖选复制，按钮、会话列表项和输入工具栏不参与普通文本选择。入口为 `hooks/useChatSelectAll.ts`，由 `components/ChatWindow.tsx` 接入。

- 消息区仅用户正文、AI 正文及代码内容可选；时间、模型名、系统提示词入口、处理状态、代码语言标签、行号和复制按钮不显示选区。复制选区时同样过滤这些元信息，保留正文段落与代码换行。正文使用 `data-message-body` 标记，代码工具栏使用 `data-selection-ignore`。

- 代码块的选中背景仅覆盖代码行的实际文字宽度，不覆盖容器内边距和行尾剩余宽度；保留源代码的缩进与真实空行，不以裁剪代码内容实现视觉效果。

## 窗口接入微信

- 微信会话绑定统一从聊天窗口入口操作；主侧栏不再展示「远程连接」区块。扫码登录与账号管理保留在微信设置中。

- 「接入微信」统一使用 AppIcon 的 wechat（Lucide MessageCircle）单个空心圆气泡，与相邻资源管理器、关闭图标统一使用 compact 14px 画布、1.75 单位描边，不叠加第二个气泡、内部圆点或手绘品牌细节。单窗口与多窗口入口均位于窗口标题栏右侧、资源管理器按钮之前。图标悬停提示和无障碍名称展示连接状态，已绑定窗口保留状态圆点。
- 每个聊天窗口提供「接入微信」入口；直接绑定同一个 Session，共用当前项目、角色、模型和历史上下文。空窗口先创建会话再绑定，不发送占位消息；已创建但尚无消息且未运行的会话继续显示项目标题、品牌名称和居中输入框，已创建会话的项目不可切换；创建完成保持空闲，只有真实消息发起执行后才显示「正在思考」和停止按钮。
- 只有一个已知微信端时点击直接接入；多个端时显示当前会话供选择。「微信已接入」可查看并解除绑定；同一个端切换窗口后仅后续消息进入新窗口，不搬移旧消息。
- 弹窗复用主题变量与原生 dialog 的焦点约束、Escape 关闭及焦点恢复。未登录或尚无微信端时提供微信设置和首条消息引导；绑定后自动启动监听；只有已登录且监听中才显示「微信已接入」，停止、登录失效和收信异常分别提示。
- 微信端处理中禁止切换和解除；窗口已有回合运行时微信消息等待其结束，再执行新回合。主人设备与 DeerHux 需在线。入口为 `components/WindowWeChatButton.tsx`，样式为 `components/window-wechat.module.css`。

- 已连接窗口支持双向文字同步：电脑端发送成功后，微信收到带「电脑端」标记的用户消息，回合完成后收到带「AI 回复」标记的最终正文。思考、工具调用和逐字更新不推送，图片仅显示文字占位；已有历史不自动回灌。微信发起的回合沿用原回复链路，不回显输入或重复推送答案。
- 同步由 `lib/wechat-session-mirror.ts` 订阅服务端会话事件实现；同一微信端顺序发送，解除绑定、切换窗口或停止监听后取消未发送的旧窗口同步。

- 微信「正在输入」在收到消息开始处理时启动，覆盖会话恢复、排队、模型和工具执行，回复发送完成或失败后结束；电脑端发起的已绑定会话同样显示。长回合每 15 秒续期，同一微信端有多个等待任务时保留状态，最后一个任务完成才关闭。状态接口失败不阻塞回复，停止监听、解除绑定时清理状态。

## 历史消息编辑

- 消息时间、系统提示词入口和 AI 消息统计默认隐藏，悬停对应消息或键盘焦点进入后显示；移出后淡出，保留元信息占位。消息 hover 使用 `MessageView.tsx` 的 `data-hovered` 与 `app/globals.css`，运行中隐藏统计、显式常显模式继续优先生效。发布构建必须核验最终 CSS 包含消息隐藏与悬停选择器。

- 每次打开历史消息编辑框后，发送按钮禁用 3 秒，颜色保持正常状态，发送处理函数同时校验时间，避免双击或连续回车误发送；期间允许输入、选区与取消，关闭时清理计时器，再次打开重新计时。

- 系统提示词弹窗底部展示“本轮 Skill 记录”，按用户选择、上下文注入、工具读取、入口调用分组显示去重胶囊；悬停查看证据路径。注入成功与否随 turn_context 持久化，历史未记录时明确提示，不用选择记录代替注入证据。工具记录仅取当前用户消息至下一条用户消息之间的成功操作；支持显式读取和简单脚本命令归属，不把回答提及、搜索结果或复杂命令字符串当作调用。

- Agent 输出期间，主输入框为空且没有附件、引用、技能或待处理粘贴时，按裸空格调用现有安全停止动作，保留已经生成的内容；输入框存在排队草稿时空格维持正常输入。IME 组合输入、按键长按和带修饰键的空格不触发停止。

## 已修改文件列表

- 列表是绑定会话与回合的不可变文件变更快照：最终结束（含停止、失败）时追加到该会话 JSONL，先保存再广播终态。关闭窗口重新打开、刷新页面或重启后，从当前分支恢复最后一轮快照；不查询文件当前状态，也不把后续外部修改写回旧快照。新回合开始隐藏旧列表，无改动的回合保存空快照；旧会话没有记录时不猜测补建。读取入口为 `lib/session-reader.ts`，首屏分页与完整历史均返回快照。

- 文件行按本轮操作前后的真实状态标记：删除文件名使用删除线与 `text-dim`；新增文件名右侧紧跟 13px 圆圈加号，使用 `accent`；编辑文件名右侧紧跟 13px 铅笔，使用 `text-muted`。图标具有悬停说明与无障碍名称，长文件名省略时图标仍可见；目录文字不加删除线。项目内外采用相同规则。
- 变更类型随工具结果、实时事件与回合结束汇总传递；同轮新增后继续编辑仍标为新增，原有文件删除后重建标为编辑。旧记录缺少类型证据时保留普通文件行，不根据文件名或当前存在性猜测类型。入口为 `lib/file-changes.ts` 与 `components/ChangedFilesList.tsx`。

- 「n 个文件被修改」下方文件行复用聊天区文件右键菜单，提供复制相对路径、复制绝对路径、打开所在文件夹（macOS 显示「在 Finder 中显示」）和使用默认应用打开。相对路径以所属会话项目目录为基准，项目外文件沿用完整路径。
- 文件列表默认最多显示 5 个文件；超过 5 个时，第 6 行显示省略图标与「查看更多」，点击后在当前列表中展示全部文件。顶部折叠按钮仍控制整个列表的显示与隐藏。
- 普通点击文件行时打开右侧资源管理器（已打开则保持打开），切换到所属项目、展开祖先目录、滚动定位并高亮文件；重复点击仍会重新定位。项目外文件以所在目录为资源根，无法定位时显示原因。定位刷新目标目录以包含刚新增的文件，并保留原有展开状态；显式定位优先于历史滚动位置恢复。
- Command/Ctrl + 点击使用默认应用打开；右键菜单沿用主题、视口边界定位、键盘导航和操作失败提示。入口为 `components/ChangedFilesList.tsx`，通过 `data-file-menu-path` 接入 `components/AiFileLinkMenu.tsx`。定位经 `ChatWorkspace`、`AppShell` 传入 `WorkspaceExplorer` 与 `FileExplorer`，文件树内点击仍打开预览。

## 思考过程展示

- 仅展示正在流式生成的当前思考块；同条消息中更早的思考块、已完成消息和历史回合中的思考全部隐藏，展开历史过程也不重新展示。
- 开始输出正文、调用工具或结束回复后隐藏思考卡片；只包含历史思考的消息不留下空的模型名和消息占位。正文、工具记录、错误提示及会话持久化内容保持原有语义。入口为 `components/MessageView.tsx`。

## macOS 灵动岛

- 刘海屏使用 `NSScreen.safeAreaInsets` 与顶部辅助区域计算中央不可见区，并额外保留安全边距；中央区域作为黑色岛体的不可见部分，禁止放置状态文字、计时、按钮或其他可交互内容，不把它表现为两个独立胶囊之间的透明空白。
- 灵动岛沿用约 460pt 的紧凑整体宽度，并把真实刘海纳入岛体。单 Session 左侧显示项目与运行符号、右侧显示状态与计时；并发 Session 才两两分布在刘海两侧，更多 Session 向下增加行；无刘海屏退化为同宽普通布局。
- Session 完成后保留完成态 5 秒再自动撤回；重连基线仅补发仍在运行的 Session，禁止已撤回的完成态被后续事件重新创建。
- 冷启动时宿主先缓存 Session 行，灵动岛页面完成事件监听注册后通过 ready 握手主动刷新快照；页面 ready 前不显示窗口，避免首次 `show()` 被后续导航或挂载覆盖。
- 灵动岛 WebView 的 `html`、`body` 与岛体外区域保持完全透明，只由胶囊、刘海填充区和展开抽屉绘制黑色背景，禁止窗口级矩形底色透出圆角。
- 窗口先完成尺寸与居中位置同步再显示，避免首次出现时以旧宽度短暂覆盖刘海。展开抽屉仍从顶部锚点向下增长，不改变顶部安全区。
