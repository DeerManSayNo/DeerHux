# DeerHux 项目功能清单

> 基线版本：`0.6.12`  
> 整理依据：当前仓库源码、API 路由、UI 组件与 `docs/agent-architecture-research.md`  
> 更新日期：2026-09-03

## 1. 项目定位

DeerHux 是一个**本地优先的 Coding Agent Harness**，同时提供 Web UI 与 Tauri 桌面客户端。它以自研 `DeerLoopEngine` 作为生产 Agent Loop，通过 HTTP/SSE 连接前端，支持模型调用、代码工具、会话管理、扩展配置、多 Agent 协作和远程消息接入。

主要运行形态：

- **桌面端**：Tauri 2 + 内嵌 Node.js 后端；
- **Web 端**：Next.js + React；
- **Agent Runtime**：TypeScript/Node.js；
- **本地数据**：JSON / JSONL 文件；
- **模型传输**：基于 `pi-ai` 对接多 Provider；
- **桌面平台**：macOS、Windows。

| 功能域 | 核心能力 |

### 2.1 产品视角速览

面向日常使用，可将现有能力归纳为六条主线：

1. **项目开发**：打开本地项目，通过 Agent 读写代码、执行命令、检索符号并查看本轮变更；
2. **持续对话**：管理多会话、多分支和长上下文，在多个聊天窗口间并行推进任务；
3. **模型接入**：管理 Provider、认证和自定义模型，在会话中切换模型、推理等级和自动恢复策略；
4. **能力扩展**：通过 Skills、MCP、CodeGraph、角色、记忆和系统提示词定制 Agent；
5. **任务协作与自动化**：使用 Subagent 拆分任务、隔离编码、回收 Diff，并通过 Cron 定时运行 Prompt；
6. **桌面与远程入口**：通过 Tauri 桌面端、快捷会话抽屉和微信 Bot 从不同入口继续同一套 Session 工作流。

## 3. 项目与工作区管理

### 3.1 多项目管理

- 按工作目录（`cwd`）组织项目和会话；
- 自动发现已有会话对应的项目；
- 支持手动选择并引入项目目录；
- 支持设置默认工作目录；
- 支持项目备注和显示名称；
- 支持项目置顶与项目列表收起/展开；
- 支持刷新项目及会话；
- 支持从侧边栏移除项目引入；
- 支持永久清空指定项目的全部会话文件；
- 跨平台处理 macOS、Linux 和 Windows 文件路径。

### 3.2 多会话工作区

- 支持同时打开多个会话；
- 根据窗口数量自动切换单、双、三、四、六窗口布局；
- 多窗口横向排列，空间不足时横向滚动；
- 每个窗口可独立切换、聚焦和清空；
- 支持多个 Agent Session 同时运行；
- 支持按窗口保存未发送的输入草稿、附件与引用；
- URL 可记录当前聚焦 Session，便于刷新后恢复；
- 会话运行状态在侧边栏和工作区同步展示。

## 4. 会话管理

### 4.1 会话浏览

- 从本地 JSONL 文件直接读取会话；
- 按项目分组展示会话列表；
- 支持搜索项目名称、会话名称和会话内容摘要；
- 展示会话创建时间、修改时间、消息数和首条消息；
- 展示正在运行的会话状态；
- 区分普通会话、Fork 子会话和 Subagent Worker 会话；
- 支持长会话按需分页加载，减少初始传输量。

### 4.2 会话操作

- 新建会话；
- 重命名会话；
- 删除单个会话；
- 清空项目下的全部会话；
- 从任意用户消息 **Fork** 为独立新 Session；
- 回退到历史节点，在同一 Session 中创建消息树分支；
- 展开、收起和切换会话分支；
- 恢复会话持久化的模型、推理等级、角色和 Agent 模式；
- 运行中保护关键操作，避免切分支或 Fork 时产生状态竞争。

### 4.3 本地持久化

- 会话以 JSONL 形式存储；
- 消息通过 `id + parentId` 构成树形历史；
- 持久化用户消息、模型消息、思考内容和工具调用结果；
- 持久化模型切换、推理等级切换、压缩摘要和分支摘要；
- 支持自定义条目，用于保存协作 Agent 等扩展状态；
- 会话异常中断后保留已落盘历史。

默认会话目录：

```text
~/.deerhux/agent/sessions/<编码后的工作目录>/<时间戳>_<uuid>.jsonl
```

可使用 `DEERHUX_CODING_AGENT_DIR` 修改 Agent 数据目录。

## 5. 智能对话体验

### 5.1 消息输入

- 多行文本输入与快捷发送；
- 输入框高度自动调整；
- 支持粘贴、选择或拖拽图片；
- 图片保存到项目 `assets/chats/` 后参与对话；
- 支持从文件树添加 `@` 文件引用；
- 支持直接选择并引用 Skill；
- 不同 Session/窗口独立保存输入草稿；
- 本地乐观消息与服务端消息自动对账；
- 通过客户端消息 ID 避免重复提交。

### 5.2 流式输出

- 通过 SSE 实时接收 Agent 事件；
- 流式展示文本和思考内容；
- Markdown 与 GFM 渲染；
- 代码块语法高亮和复制；
- 展示模型、Provider、Token、费用及运行耗时；
- 展示当前工具状态与 Agent 运行阶段；
- 支持停止当前 Agent 或压缩任务；
- Agent 完成时可播放提示音。

### 5.3 消息内容展示

- 用户消息、Assistant 消息、Tool Result 分层展示；
- 思考过程可折叠；
- 工具调用参数、结果和错误可查看；
- 消息与代码内容可复制；
- 支持图片消息；
- 支持 Subagent 协作运行卡片；
- 支持对话缩略图/迷你图快速定位长会话；
- 支持显示本轮变更文件并直接打开。

### 5.4 运行中消息控制

- **Abort**：中止当前运行及正在执行的工具；
- **Steer**：在 Agent 运行中注入引导消息；
- **Follow-up**：将消息排队，在当前任务结束后继续执行；
- 中止会终止 Shell 进程树，避免仅停止父 Shell 而遗留子进程。

### 5.5 快捷会话

- 桌面端通过全局快捷键快速显示或隐藏独立会话抽屉；
- 通过另一组全局快捷键直接打开临时新会话；
- 最多聚合最近 6 个非 Subagent 会话，并优先展示最近活动会话；
- 支持单会话与三会话展开视图、横向滚动和键盘导航；
- 每张会话卡可直接对话、新建会话、引用项目文件或从快捷列表隐藏；
- 可锁定抽屉，控制失去焦点后是否自动收起；
- 新会话首次发送前保留临时草稿，发送后自动替换为真实 Session；
- 快捷窗口复用主聊天能力，包括流式响应、角色、模型、文件引用和分支操作。

## 6. Agent 工作模式

| 模式 | 定位 | 默认能力 |
|---|---|---|
| Ask | 只读问答 | 阅读、搜索、分析，不修改文件或运行 Shell |
| Plan | 先研究再实施 | 输出包含文件、风险和验证步骤的计划，等待 Build |
| Agent | 完整执行 | 可读写文件、运行命令并完成验证 |

其他能力：

- 模式约束会注入当前 Turn 的提示词；
- Ask/Plan 使用只读工具集合；
- Plan 完成后可进入 Build/Agent 阶段实施；
- 模式随会话状态恢复，并可在对话中切换。

## 7. 模型与推理配置

### 7.1 多 Provider 接入

项目基于 Pi 模型目录和流式传输层，可配置多类 Provider，包括：

- Anthropic；
- OpenAI / OpenAI Codex；
- Google / Vertex AI；
- DeepSeek、Groq、Mistral；
- Moonshot / Kimi、MiniMax、Qwen、智谱；
- OpenRouter、Together、Fireworks、Cerebras；
- GitHub Copilot；
- Amazon Bedrock；
- Azure OpenAI；
- Cloudflare / Vercel AI Gateway；
- 其他 OpenAI、Anthropic、Google 兼容 API。

### 7.2 Provider 认证

- OAuth 登录与退出；
- Device Code 登录流程；
- API Key 配置；
- 展示 Provider 登录/配置状态；
- 支持自定义 Base URL、Headers 和兼容参数；
- 敏感配置在界面中使用密码字段处理。

### 7.3 模型管理

- 新增、编辑和删除 Provider/模型配置；
- 配置模型名称、API 协议、上下文窗口和最大输出 Token；
- 配置文本/图片输入能力；
- 配置 Reasoning、成本和兼容选项；
- 测试模型连接并显示延迟、HTTP 状态和调试信息；
- 设置默认模型；
- 对话过程中切换模型；
- 模型选择写入 Session 历史并在恢复时还原。

### 7.4 推理等级

支持以下推理强度：

```text
auto / off / minimal / low / medium / high / xhigh
```

- 根据模型能力展示可用等级；
- 支持为不同模型配置推理等级映射；
- 推理等级变更写入 Session 历史。

### 7.5 自动恢复模型

- 可配置按顺序尝试的备用模型列表；
- 对可恢复的上游错误进行自动重试；
- 支持 TTFT 超时、限流和服务过载分类；
- 连续失败的上游会临时进入进程级冷却；
- UI 展示重试次数、延迟和恢复状态；
- 用户可关闭自动恢复或手动停止重试。

## 8. Agent Loop 与工具能力

### 8.1 自研 Agent Loop

`DeerLoopEngine` 负责：

- Prompt/Turn 状态管理；
- LLM 流式响应消费；
- 多轮工具调用循环；
- 工具并行或串行执行；
- Steering 与 Follow-up 队列；
- 自动重试、退避和中止；
- 模型与推理等级切换；
- Session 导航与 Fork；
- 上下文压缩和归档；
- 统一运行事件输出。

### 8.2 内置编码工具

| 工具 | 功能 |
|---|---|
| `read` | 按行读取文本文件 |
| `write` | 创建或覆盖文件 |
| `edit` | 精确替换文件内容 |
| `bash` | 执行 Shell 命令，支持超时和中止 |
| `grep` | 文本检索 |
| `find` | 文件查找 |
| `ls` | 目录浏览 |
| `code_search` | 搜索本地代码索引 |
| `codegraph` | 符号、调用关系和影响分析 |
| `subagent` | 创建协作 Agent 任务 |

### 8.3 工具执行管理

- 统一 `ToolRegistry` 管理工具注册与激活白名单；
- 可按 Agent 模式限制模型可见工具；
- 支持工具并行/串行执行语义；
- 工具错误彼此隔离，不直接破坏整个循环；
- 支持执行前 Guard、执行后 Hook 和结果处理管线；
- 大型工具输出自动截断并归档，避免挤占模型上下文；
- 文件修改工具回报变更文件；
- MCP 配置更新后可对活动 Session 热刷新工具集。

### 8.4 代码索引与 CodeGraph

- 扫描项目代码并建立本地索引；
- 查看索引状态；
- 手动刷新索引；
- 按关键词检索文件、行号和代码片段；
- 检测 CodeGraph 是否可用；
- 查询函数、类、组件和接口等符号；
- 查询 callers、callees 和变更影响范围。

## 9. 上下文与压缩

### 9.1 上下文构建

- 从当前 Session Leaf 构建有效消息路径；
- 支持树形分支而非只读取文件尾部；
- 恢复模型、推理等级、角色和模式状态；
- 后续 Turn 将历史图片降级为文本占位，避免重复发送；
- 文件引用、Skill 引用和 Turn 模式以结构化上下文参与请求；
- 长输出保存到 Session 专属上下文归档目录。

### 9.2 会话压缩

- 手动压缩长会话；
- 发送前根据上下文使用量提示压缩；
- 压缩期间可取消；
- 压缩结果写入 Session；
- 保存摘要、压缩前 Token 数和首个保留条目；
- 历史转录可归档到文件，避免只保留不可追溯摘要；
- 保持对新旧压缩 SSE 事件名的兼容。

### 9.3 用量信息

- 展示当前上下文窗口占用比例；
- 统计 Input、Output、Cache Read、Cache Write Token；
- 展示模型调用成本；
- 长会话使用分页和快照机制降低前端加载压力。

## 10. 多 Agent / Subagent 协作

### 10.1 任务模式

- Ask：委派只读调研；
- Code：委派编码任务；
- Parallel：并行拆分任务；
- Review：委派审查任务；
- Custom：自定义 Worker 任务。

### 10.2 隔离与调度

- **analysis**：在共享工作目录中执行只读分析；
- **isolated_coding**：在独立 Git Worktree 中编码；
- 支持前台和后台运行；
- 支持并行、串行和 Pipeline 工作流；
- 可声明 DAG 工作流意图；
- 支持显式 Worker 列表或由 LLM 自动规划；
- 控制全局和单次运行的并发配额；
- Worker 使用独立 Session，避免直接共享父 Agent 完整上下文。

### 10.3 运行管理

- 展示 Worker 状态、当前工具和最近工具记录；
- 实时聚合 Worker 事件；
- 支持中止整个协作运行；
- 支持从 JSONL 恢复可继续的 Worker；
- 记录运行快照、结果、错误和汇总；
- 父 Session 保存协作任务展示快照；
- 前台运行会等待 Worker 完成，并将聚合结果返回当前 Agent Turn；
- 后台运行可在父 Agent 继续其他工作时保持执行。

### 10.4 代码结果回收

- 生成每个 Worker 的 Git Diff 与统计；
- 显示修改文件和冲突文件；
- 支持将 Worktree 补丁应用回主工作区；
- 跟踪已应用、失败和冲突结果；
- 默认拒绝在 Dirty Git Worktree 上启动隔离编码，保护未提交改动。

## 11. 角色、记忆与系统提示词

### 11.1 角色管理

- 内置默认角色；
- 创建、编辑和删除自定义角色；
- 支持全局角色和项目角色；
- 角色包含名称、描述和基础 Prompt；
- 角色设定分为：
  - Identity：身份与职责；
  - Soul：语气与风格；
  - Rules：行为规则；
  - User：用户偏好；
  - Tools：工具使用规则；
  - Memory：角色长期记忆；
- 对话中可切换角色；
- 可从用户自然语言建议新增角色设定；
- 长期角色设定写入前由用户确认。

### 11.2 长期记忆

- 全局记忆对所有角色和 Session 生效；
- 角色记忆只注入对应角色；
- 支持新增、编辑、删除长期记忆；
- 角色页面与记忆页面双向同步；
- 加载失败时阻止覆盖保存，保护已有数据。

### 11.3 系统提示词

- 将系统提示词拆分为多个可开关 Section；
- 支持编辑可配置 Section；
- 支持保存、命名和恢复提示词版本；
- 为角色选择可用 Skills；
- 为角色选择可用 MCP Tools；
- 根据 Agent 模式动态注入模式约束；
- 支持查看最终组合后的提示词结构。

## 12. Skills、MCP 与扩展

### 12.1 Skills

- 加载内置、全局、项目和路径来源的 Skill；
- 按来源和子来源分组展示；
- 搜索远程 Skill；
- 从 `skills.sh` 安装 Skill；
- 支持安装到全局或项目范围；
- 删除可管理的 Skill；
- 设置主动调用或模型被动匹配；
- 输入框中明确引用 Skill；
- 展示 Skill 路径、来源和描述。

### 12.2 Tavily 搜索配置

- 配置 Tavily API Key；
- 掩码展示已保存的 Key；
- 测试 Tavily 连接；
- 供相关联网搜索 Skill/MCP 能力使用。

### 12.3 MCP 服务

- 测试服务连接并展示工具数量和错误；
- 显示配置来源与运行状态；
- 保存配置后热刷新活动 Session 的 MCP 工具；

### 12.4 扩展总览

- 汇总当前项目实际加载的 Skills；
- 汇总 MCP 服务及实时连接状态；
- 汇总内置、索引、CodeGraph 和 MCP 工具；
- 汇总角色；
- 展示 Resource Loader 和扩展诊断信息；
- 显示启用数量、来源、可导入/可管理状态及警告。

## 13. 文件浏览与预览

### 13.1 文件资源管理器

- 浏览项目目录树；

## 19. 安全与数据保护

当前已实现：

- 本地优先存储，Session 默认保存在用户目录；
- 文件工具默认限制在当前 `cwd` 或允许的资源根目录；
- 文件 API 校验访问路径；
- 工具白名单控制模型可见能力；
- Ask/Plan 模式限制为只读工具；
- Shell 命令支持超时、中止和进程树清理；
- 大输出截断与归档，防止上下文失控；
- Session 持久化失败时安全停止，避免产生不可恢复历史；
- 配置加载失败时禁止覆盖保存；
- 隔离编码默认保护 Dirty Git 工作区；
- 日志文件使用受限权限并自动轮转。

当前边界：

- 工具白名单不等同于完整 OS 沙箱；
- 尚未形成统一的命令、网络、秘密信息和人工审批策略；
- 单机运行时状态主要保存在进程内，不适用于直接水平扩容。

## 20. 已知限制与能力边界

1. **MCP 传输**：配置模型包含 `stdio`、`SSE` 和 `HTTP`，当前稳定运行主路径以 `stdio` 为主；扩展总览会将尚未支持的 HTTP/SSE Runtime 标记为 unsupported。
2. **Subagent DAG**：可声明 `dag` 工作流，但当前 MVP 会按声明顺序降级为串行执行，尚未实现完整拓扑调度。
3. **隔离编码**：稳定产品路径要求 Git 仓库；默认拒绝 Dirty Worktree。底层非 Git 临时目录复制不等于完整可审核的产品流程。
4. **事件存储**：实时 Event Store 与上游健康状态主要为进程内数据，后端重启后依赖 JSONL Session 快照恢复。
5. **部署形态**：当前面向本机单用户、单 Node 后端进程，不是多租户云端 Agent 平台。
6. **安全模型**：当前具备路径约束、工具白名单和模式限制，但尚无完整 OS 沙箱、网络出口治理和统一人工审批。
7. **会话存储抽象**：Session 浏览直接读取 JSONL；Agent Loop 的部分压缩和上下文能力仍依赖 Pi `SessionManager` 语义，尚不能无成本切换数据库。
8. **桌面构建**：Tauri 不支持 macOS/Windows 交叉编译，需要在目标平台分别构建。
9. **变更记录持久化**：普通 Chat Session 的回合文件变更账本当前保存在运行期内存中；刷新后不保证恢复历史变更卡片。
