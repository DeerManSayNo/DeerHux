# ADR：Worktree 协作隔离与后续进程沙箱

日期：2026-09-05。状态：采用协作隔离边界；OS 沙箱实现延期，未启用。

## 决定

当前生产执行仍由 `DeerLoopEngine` 承担。Worktree 隔离普通 Git 源码工作目录，管理端通过仓库身份、manifest、事务、锁、实时事实与保守保留规则防止误删和错误 Apply。它不隔离 Worker 进程的用户权限、网络、主工作区、用户文件或 Git common directory。

Worker 标准工具由 `agentCwd` 启动；`read` 可以访问本机绝对路径，`bash` 仍可启动拥有宿主用户权限的任意命令。`edit/write` 的路径约束并不构成 Bash 的约束。过滤子进程继承环境只能减少意外传递凭据，不能阻止命令自行读取文件、启动其他解释器或访问网络。

可信边界为用户明确授权、宿主管理代码和受保护的用户侧配置。仓库声明、Worker 输出、patch、manifest 内容仍需重新校验；仓库内的 hook 脚本只有经过外部用户配置 opt-in 才能执行，但这一授权不代表其依赖代码已通过安全审计。

| 威胁 | 当前防护目标 | 不承诺的能力 |
| --- | --- | --- |
| 误操作、名称歧义、重复请求 | 稳定 workerId、版本前置条件、幂等事务、空选择拒绝 | 自动猜测用户意图 |
| 失控或崩溃的命令 | 超时/取消、进程组终止、成果捕获、保留和恢复 | 阻止任意脱离进程组的进程或越权文件访问 |
| 恶意 Prompt 或仓库输入 | 管理端严格路径、所有权和 artifact 验证 | 限制高权限 Bash 主动操作主仓库、其他文件或网络 |
| 供应链和 setup hook | 外部可信 opt-in、最小继承环境、有界执行 | 审计全部 imports、安装脚本与依赖；保护同 UID 的秘密 |

## 后续沙箱方案的准入门槛

macOS 与 Linux 必须分别提交实现 ADR 和真实平台测试，不能把一端的机制名称直接当成另一端已经具备的安全能力。选型需证明：默认只读或不挂载主工作区与其他 Worktree；Git common dir 的访问经过受控代理或明确限制；可写依赖仅归当前 Worker；工具链和共享缓存是强制只读；网络策略独立配置；模型凭据留在沙箱外的传输代理；取消和重启不会留下仍在写入的进程。

未达到这些门槛前，UI/设置/文档统一使用“协作隔离”，不得宣称“安全沙箱”。本 ADR 不引入新的沙箱、网络开关或自动安装，不改变 Pi/DeerLoopEngine 的职责边界。
