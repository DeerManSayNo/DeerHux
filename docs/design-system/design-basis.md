# 设计依据

## 用户任务

主要用户是在桌面端持续使用 Agent 完成编码工作的开发者。核心任务是选择项目和会话、与 Agent 对话、观察流式运行与工具状态、审阅文件和变更，并在多个并行窗口间切换。完成条件是当前上下文、运行状态和下一步操作始终可辨识且可达。

## 信息与操作关系

- 会话内容、当前运行状态和输入操作优先；项目导航、资源管理器与文件预览提供上下文支持。
- 每个局部范围只突出一个主操作。常规、弱操作与破坏性操作使用不同层级。
- 主工作台承载持续任务，配置与短确认进入二级弹窗，菜单和预览使用不改变底层布局的临时浮层。
- loading、empty、disabled、error、success、停止和重试属于任务状态，反馈留在用户当前上下文并提供恢复路径。

## 视觉方向

- 使用安静、紧凑、可扫描的工作台构图，支持高频操作和高信息密度。
- 层级主要由表面、字号、字重、间距和必要边界表达，保持连续工作区；一个表面只使用一种主要边界信号，避免装饰性卡片、细线框和容器嵌套堆叠。
- 橙色承担品牌、主操作和选中反馈；成功、警告、危险、信息使用独立语义色。
- 明暗主题共享信息结构和组件体系，默认深色。动效只表达状态连续性和空间关系。
- 中文是当前产品语言；路径、代码、模型 ID 和技术参数使用等宽字体并允许选择或复制。

## 范围与取舍

- 本设计系统适用于主工作台、聊天、配置弹窗、文件与资源面板及相关辅助窗口。
- 领域页面可补充局部契约，但不能重定义全局 Token 和基础组件语义。
- 现有源码是实现证据。只有本设计系统明确采纳的规则才是规范；历史硬编码和局部偏差保留为渐进迁移项。
- 当前没有 Figma 权威来源。设计值以项目 Token 为准，行为与 API 以共享组件源码为准。
- 2026-09 的分享窗口与模型配置改造已确认采用“低轮廓配置界面”：输入控件保留可编辑边界，导航、分组、状态和操作优先通过邻近、表面与排版表达；该方向作为其余二级窗口迁移依据。
